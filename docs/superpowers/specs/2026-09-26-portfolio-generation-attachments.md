# 명함 생성 첨부파일 설계

## 목표

Create 페이지에서 선택한 첨부파일을 명함 생성 요청과 함께 백엔드로 전달하고, S3에 저장한 뒤 생성된 포트폴리오에 연결한다.

## 범위

- 첨부파일은 명함 생성 시점에만 받는다.
- 생성 후 첨부파일 목록 조회·수정·사용자 삭제 화면은 만들지 않는다.
- 지원 형식은 현재 프론트 계약에 맞춰 PDF, JPG, PNG로 한다.
- 파일은 S3 비공개 버킷에 저장한다.
- 포트폴리오 생성이 실패하면 해당 요청에서 업로드한 S3 객체를 정리한다.
- AI가 파일 내용을 실제로 추출·생성하는 로직은 별도 작업이며, 이번 작업은 전달·저장·연결 계약까지 담당한다.

## API 계약

`POST /portfolios/generate`는 기존 JSON 대신 `multipart/form-data`를 허용한다.

- 일반 필드: `title`, `cardDesignId`, `siteDesignId`, `externalLinks`, `requirements`
- `externalLinks`: JSON 문자열 배열
- `attachments`: PDF/JPG/PNG 파일 여러 개
- 파일 개수와 용량 제한은 서버 상수로 관리하며, 초과 시 구체적인 4xx 오류를 반환한다.

응답의 `portfolio.attachments`에는 다음 메타데이터를 포함한다.

- `originalName`
- `mimeType`
- `size`

S3 객체 키와 자격 증명은 응답에 노출하지 않는다.

## 저장 구조

`PortfolioAttachment` 모델을 추가한다.

- `id`
- `portfolioId`
- `s3Key`
- `originalName`
- `mimeType`
- `size`
- `createdAt`

포트폴리오 생성 트랜잭션 전에 파일을 S3에 올리고, 포트폴리오 생성 성공 후 메타데이터를 저장한다. DB 저장 실패나 생성 실패 시 이번 요청에서 업로드한 객체를 best-effort로 삭제한다.

## 보안 및 오류 처리

- 인증된 사용자만 생성할 수 있다.
- 파일은 메모리 버퍼로 받고 허용 MIME 타입과 용량을 검증한다.
- 버킷은 공개하지 않는다.
- 다운로드 URL이나 파일 다운로드 API는 이번 범위에 포함하지 않는다.
- 파일 누락, 타입 오류, 용량 초과, S3 실패는 generic 500이 아닌 구체적인 오류 코드로 응답한다.

## 성공 기준

- 프론트가 파일을 포함한 명함 생성 요청을 보낼 수 있다.
- 생성 성공 시 S3 객체와 포트폴리오 첨부파일 메타데이터가 연결된다.
- 생성 실패 시 고아 S3 객체가 남지 않도록 정리한다.
- 기존 JSON 생성 요청과 기존 포트폴리오 기능이 회귀하지 않는다.
